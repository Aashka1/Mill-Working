# Deploying AgriMill for free

The whole app runs as **one** service: FastAPI serves the API *and* the compiled
React build from the same origin. That is deliberate — auth is cookie-only
(`httponly; secure; samesite=none`, no Bearer fallback in the frontend), so a
split frontend/backend deploy would make the session cookie a third-party
cookie and Safari would silently drop it. Same origin keeps it first-party.

Total cost: **$0**. Two free accounts: MongoDB Atlas + Render.

---

## 1. Database — MongoDB Atlas (free M0)

1. Sign up at <https://www.mongodb.com/cloud/atlas/register>.
2. Create a **free M0** cluster (any provider/region; pick one near you).
3. **Database Access** → *Add New Database User*. Username + a generated
   password. Save the password.
4. **Network Access** → *Add IP Address* → **Allow access from anywhere**
   (`0.0.0.0/0`). Render's free tier has no static outbound IP, so an allowlist
   will not work.
5. **Connect** → *Drivers* → copy the SRV string. It looks like:

   ```
   mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```

   Substitute the real password. If it contains `@ : / ? # [ ] %`, URL-encode
   those characters or the string will not parse.

## 2. App — Render (free web service)

1. Sign up at <https://render.com> with GitHub and grant access to this repo.
2. **New** → **Blueprint** → pick `Mill-Working`. Render reads `render.yaml`
   and provisions a Docker web service on the free plan.
3. It will prompt for the env vars marked `sync: false`:

   | Variable         | Value                                            |
   | ---------------- | ------------------------------------------------ |
   | `MONGO_URL`      | the Atlas SRV string from step 1                 |
   | `ADMIN_EMAIL`    | your login email                                 |
   | `ADMIN_PASSWORD` | **a strong password** — see the warning below    |

   `DB_NAME` defaults to `agrimill` and `JWT_SECRET` is generated by Render.

4. Deploy. First build takes ~5 minutes (yarn install + webpack + pip).
   You get `https://agrimill-xxxx.onrender.com`.

Prefer clicking through manually instead of the blueprint? **New → Web Service**,
select the repo, Runtime **Docker**, Plan **Free**, health check path
`/api/health`, then add all five env vars by hand.

### Free-tier behaviour

The service **sleeps after 15 minutes of inactivity**. The next request wakes it
and takes roughly 50 seconds. Atlas M0 gives 512 MB of storage. Both are fine
for a demo or light real use; neither expires.

## Set a real admin password

`backend/server.py` seeds an admin account on every startup and **falls back to
`admin@agrimill.com` / `admin123` when `ADMIN_EMAIL` / `ADMIN_PASSWORD` are
unset**. It also *resets* the stored password to match `ADMIN_PASSWORD` on each
boot. Deploying without setting these publishes an app whose credentials are in
this repo. There is also a seeded `staff@agrimill.com` / `staff123` account —
delete it from **Settings** after your first login.

## Running it locally

```bash
cp backend/.env.example backend/.env     # then fill in MONGO_URL and JWT_SECRET

cd backend && pip install -r requirements.txt && uvicorn server:app --reload
cd frontend && yarn install && yarn start   # http://localhost:3000
```

Local dev still runs the two servers separately; the static-serving block in
`server.py` is skipped when `backend/static/` does not exist.

To exercise the real production image instead:

```bash
docker build -t agrimill .
docker run -p 8000:8000 \
  -e MONGO_URL="mongodb://host.docker.internal:27017" \
  -e DB_NAME=agrimill -e JWT_SECRET="$(openssl rand -hex 32)" \
  -e ADMIN_EMAIL=you@example.com -e ADMIN_PASSWORD='...' \
  agrimill
```

## What was changed to make this deployable

- `backend/requirements.txt` — was a 130-package Emergent environment dump that
  cannot install anywhere else: it pins a `litellm` wheel hosted on
  `customer-assets.emergentagent.com` and `emergentintegrations==0.2.0`, which
  is not on PyPI. Replaced with the 13 packages `server.py` actually imports.
  The original is kept at `backend/requirements-emergent.txt`.
- `backend/server.py` — added `GET /api/health`, plus static serving of the
  React build with an SPA fallback so deep links like `/inventory` work on
  refresh. Unmatched `/api/*` paths still 404 rather than returning the HTML
  shell, and the file resolver is constrained to the build directory.
- `frontend/src/lib/api.js` — `REACT_APP_BACKEND_URL` had no fallback, so an
  unset var produced the literal URL `"undefined/api"`. Now defaults to
  same-origin.
- `Dockerfile` — multi-stage: Node 20 builds the frontend, Python 3.11 serves
  it. It drops the `@emergentbase/visual-edits` devDependency, a tarball fetched
  from `assets.emergent.sh` that is dev-only (`craco.config.js` gates it behind
  `NODE_ENV !== "production"`), so builds do not depend on that host.
- `render.yaml`, `.dockerignore`, `backend/.env.example` — new.

Verified locally: image builds, container boots against MongoDB, `/api/health`
returns 200, login sets the HttpOnly cookie, authenticated endpoints return 200
with it and 401 without, and deep SPA routes resolve.
